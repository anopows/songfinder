# November 13 follow-up release

## What changed

- Confirmed recording metadata owns the displayed title and performer, including saved
  results. An earlier recognition hint cannot overwrite it. Link hints also require
  matching performer metadata; Spotify search uses the confirmed candidate's identity.
- A persistent SQLite landmark index proposes up to 12 cached recordings before online
  recognition or a full catalogue scan. Every candidate still passes audio verification.
  Missing/corrupt indexes fall back to the existing scan.
- Discovery and confirmation use separate passages. Confirmation cannot refit the time
  mapping; spectral detail and attack agreement supplement existing similarity, coverage,
  wrong-offset and timing checks.
- The uploader's browser can retry retained audio with title/performer clues, cancel work,
  and renew verification without losing ownership. Retries inherit the original audio's
  expiry. A shared result link conveys neither ownership nor audio access.
- Related arrangements, unconfirmed leads, unavailable sources, timeout and cancellation
  have distinct result messages. Negative feedback leads to the correction form.
- The homepage has search and social metadata. Result, API and admin routes remain
  unindexed. Private admin metrics show queue/search times and source issues.
- Database backups use SQLite's online backup API, private file permissions and an
  isolated restoration/integrity check. Migration only adds fields.

## Prioritized review fixes

Empty upload reservations expire after three minutes and partially received uploads
idle for five minutes expire on admission, independently of the hourly purge. Active
uploads have caps of three per IP and twenty globally; only queued/working jobs occupy
the ten-place search queue. Completion checks that queue cap atomically.

Verification refreshes during activity; expiry and re-verification preserve upload
ownership. Any frontend API 401 exposes browser verification, including old feedback
pages. A title is a clue: unsuccessful title searches fall back to normal recognition.
Title and performer fields appear before the automatic upload button.

Interrupted workers resume retained audio (up to two automatic attempts). Decode
limits produce a file error, distinct from search timeouts. Failed file selections
reset, and the frontend reads the server's size limit. Seeded/confirmed references are
pinned against eviction, and other references use refreshed last-use times. The private
admin page has a delete-result control. The obsolete prototype server is removed;
formatting and progress text now live in `songfinder/presentation.py`.

## Measured evidence

The automated suite has 50 Python tests and three frontend tests. It covers
presentation, matching, retrieval, ownership, expiry, upload retry, cancellation,
privacy, metrics, restoration, abandoned reservations, time advanced by 3601 seconds,
title fallback and worker recovery. Deployment/browser checks are separately recorded
in the completion report.

The synthetic set was frozen before verification changes: three new tune seeds, each
with clean, slowed/noisy, alternate-performance and unrelated examples. Baseline: 10/12
cases passed, including one false exact and one false probable. Held-out verification:
11/12 passed, eliminating the false probable while preserving all six true exacts.
**One synthetic alternate performance still produces a false exact.** This is a known
limitation, not a passing accuracy claim. The benchmark returns nonzero while it remains.

The separate public-preview evaluation uses three recordings not used to adjust this
release's thresholds: Louis Armstrong, Cab Calloway and Hugh Laurie performances of
*St. James Infirmary*. Original, 92.6% resampled and simulated room variants were each
compared with all three references: 7/9 true variants exact, 2/9 probable, and no false
exacts in 18 cross-performance comparisons. Both probable cases were also probable with
the previous matcher. The three-reference shortlist included the true recording for
all variants. Performer identities are source metadata; positive labels come from
known audio transformations. This is not a blind human-labelled field evaluation.

Machine-readable evidence (no recordings):

- [Frozen synthetic baseline](../benchmarks/baseline-synthetic.json)
- [Held-out synthetic comparison](../benchmarks/heldout-synthetic.json)
- [Public preview comparisons and source links](../benchmarks/public-preview-pairs.json)

On the deployed VPS's 1,452-reference catalogue, the two established public smoke clips
produced 12-reference shortlists in 0.354 and 0.366 seconds. Verification reached the
correct recording in another 0.171 and 0.363 seconds. Peak RSS for that check was about
147 MiB. These timings exclude decoding, queueing and listening-link lookup; they are
not whole-service latency or a tail-latency benchmark under load.

## Reproduce and operate

```sh
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 .venv/bin/python -m pytest tests -q
node --test tests/frontend.test.cjs
.venv/bin/python tools/benchmark.py --output /tmp/songfinder-synthetic.json
# External labelled local audio: manifest cases have id/query/reference/expected.
.venv/bin/python tools/benchmark.py --manifest /private/evaluation.json --output /tmp/evaluation.json
# Apple previews plus same-stem API metadata JSON, obtained separately:
.venv/bin/python tools/public_preview_eval.py --audio-dir /private/previews --output /tmp/previews.json
# Existing reference caches need a one-time index build; new references index automatically:
.venv/bin/python -m songfinder.retrieval /var/lib/songfinder/cache
# Run with the data directory and permissions of your installation:
SONGFINDER_DATA=/var/lib/songfinder .venv/bin/python -m songfinder.maintenance /private/backup.sqlite3
```

The database backup does not include retained audio, the optional reference cache or
runtime secrets. Keep backups private. Restoring an older database must not bypass
original audio/result expiry. API/worker code can be rolled back together because the
schema changes are additive; keep the pre-release code and database backup until the
new release has been validated.

Remaining evaluation work: a larger human-labelled field set, empty-cache discovery,
provider outages and request cost, sustained concurrent load, speech/edit-aware passage
selection, and real Android interrupted uploads. Browser testing on a desktop is not
an Android-device test. Do not interpret the earlier investigated 40 clips as blind accuracy.
